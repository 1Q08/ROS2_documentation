接口（话题、服务、动作）
========================

ROS 中的接口定义了节点之间如何交换数据。
本文解释了不同类型的 ROS 接口以及它们之间的区别。
有了这些信息，你就能够为自己的用途选择合适的接口。

总结
----

ROS 节点通常通过以下三种类型的接口进行通信：

* 话题：用于连续的数据流。
* 服务：用于同步的请求/响应交互（立即完成的短任务）。
* 动作：用于带反馈的长时间运行任务（可能需要一些时间才能完成的任务）。

为实现一致的通信，每种接口都使用 ``.msg``、``.srv`` 或 ``.action`` 文件中提供的定义。

:doc:`了解更多关于节点的内容 <About-Nodes>`

话题
----

话题接口用于连续的数据流，例如流式传输传感器数据或机器人的状态。
话题定义存储在 ``.msg`` 文件中。
话题实现了发布/订阅模式。
一个节点向话题发布数据，其他节点订阅以接收这些数据。
这种接口类型具有以下主要特征：

* 异步、单向通信
* 多个发布者和订阅者可以共享同一个话题

.. mermaid::

   flowchart LR
    P[Publisher node] -->|Publishes messages| T[Topic]
    T -->|Delivers messages| S1[Subscriber node]
    T -->|Delivers messages| S2[Subscriber node]

话题键（topic key）用于标识话题上的各个发布者，以便节点和工具能够区分消息的来源。
当多个发布者共享同一个话题时，每个话题键都有助于更轻松地追踪数据来源。

话题统计
--------
话题统计是内置的度量机制，帮助你了解消息在被订阅接收时的表现。
启用后，它会自动跟踪两项内容：

:消息年龄: 消息到达时的存续时间，基于其时间戳。
:消息周期: 相邻两条消息之间的时间间隔。

对于消息年龄和周期，ROS 使用一个滑动窗口（每收到一条新消息就更新一次）来计算平均值、最小值、最大值、标准差和样本数。
这些计算借助专用工具以恒定时间和恒定内存运行。
当你为某个订阅启用话题统计时，ROS 会以固定间隔在统计话题上将收集到的数据作为 ``MetricsMessage`` 发布。
这让你能清楚地看到时序模式、延迟和异常情况，从而更容易评估系统性能或诊断与消息流相关的问题。

.. tip::

   默认间隔为 1 秒。
   默认统计话题为 ``/statistics``。

:doc:`了解如何启用话题统计 </Tutorials/Advanced/Topic-Statistics-Tutorial/Topic-Statistics-Tutorial>`

服务
----

服务接口用于同步的请求/响应交互，例如，当你想要发送一个查询来请求某个特定机器人的配置时。
服务定义存储在 ``.srv`` 文件中。
服务实现了请求/响应模式。
客户端发送请求，服务器以响应进行回复。
这种接口类型具有以下主要特征：

* 同步通信
* 非常适合需要确认的短时操作，或响应请求并提供结果

.. mermaid::

   sequenceDiagram
    participant Service client
    participant Service server
    Service client->>Service server: Request
    Service server-->>Service client: Response

动作
----

动作接口用于带反馈的长时间运行任务，例如将机器人移动到特定位置，或要求机器人执行复杂的运动。
动作定义存储在 ``.action`` 文件中。
动作允许客户端发送目标、在执行过程中接收反馈、在需要时取消，并在有结果时返回结果。
这种接口类型具有以下主要特征：

* 异步，带反馈和结果
* 适合需要时间的操作

.. mermaid::

   sequenceDiagram
    participant Action client
    participant Action server
    Client->>Action Server: Sends a goal
    Action server-->>Action client: Provides feedback (periodic)
    Action server-->>Action client: Sends a result

ROS 接口之间的主要区别
----------------------

这三种接口都能实现节点之间的通信，但各自服务于不同的目的。
下表总结了 ROS 接口类型之间的区别：

+--------------+----------------------+-----------------------+-----------------+--------------------+---------------+
|              | 模式                 | 方向                  | 提供结果        | 典型用例           | 取消          |
+==============+======================+=======================+=================+====================+===============+
| **话题**     | 发布/订阅            | 单向                  | 否              | 连续数据           | 不支持        |
+--------------+----------------------+-----------------------+-----------------+--------------------+---------------+
| **服务**     | 请求/响应            | 双向                  | 是              | 快速查询           | 不支持        |
+--------------+----------------------+-----------------------+-----------------+--------------------+---------------+
| **动作**     | 目标/反馈/结果       | 带反馈的双向          | 是              | 长时间运行的任务   | 支持          |
+--------------+----------------------+-----------------------+-----------------+--------------------+---------------+
