为 ROS 2 包编写文档
###################

.. contents:: 目录
   :depth: 2
   :local:


本指南介绍为 ROS 2 包创建文档的标准方式。
对于有二进制发布的包，这也会使文档托管在 ``docs.ros.org/en/<distro>/p/<package>/``。
有关如何向 docs.ros.org 上的此文档做出贡献的信息，请参见 :doc:`为 ROS 2 文档做贡献 <../The-ROS2-Project/Contributing/Contributing-To-ROS-2-Documentation>`。

前提条件
--------

- :doc:`安装 ROS <../../Installation>`

- `安装 rosdoc2 <https://github.com/ros-infrastructure/rosdoc2#installation>`__

包文档概述
----------

本指南讨论的文档类型被称为"包文档"或"API 文档"。
对于已在 ROS Index 上发布的 ROS 包，其文档将在 ROS 构建农场（buildfarm）上构建，收录到 docs.ros.org，并可通过 index.ros.org 上的 ``API Docs`` 按钮访问。

负责生成 ROS 2 包文档的工具是 `rosdoc2 <https://github.com/ros-infrastructure/rosdoc2>`__。

``rosdoc2`` 是对常用的 `Sphinx <https://www.sphinx-doc.org/>`__ 文档框架的一个便捷封装。
Sphinx 允许自由格式的书面文档，以及根据代码中的注释生成的 Python 代码 API 文档。
`breathe <https://breathe.readthedocs.io/en/latest/>`__ + `exhale <https://exhale.readthedocs.io/en/latest/>`__ 包允许与 Doxygen 集成，以包含自动生成的 C++ API 文档。

``rosdoc2`` 会为完全没有文档或配置的包创建默认配置，并应用统一主题以及与其他包集成的选项。

构建包文档
----------

要使用 ``rosdoc2`` 以 HTML 格式生成包的文档，请运行：

.. code-block:: console

   $ rosdoc2 build --package-path <package-path>

文档会写入 ``docs_output/<package-name>/index.html``，并可在浏览器中查看。

配置
----

ROS 包文档有三个配置位置：用于通用设置的 ``rosdoc2.yaml``、
用于 Sphinx 设置的 ``conf.py`` 以及用于 Doxygen 设置的 ``Doxyfile``。
对于所有这些配置，如果不存在，都会假定或生成默认值，因此严格来说它们都不是必需的。
但是，一旦你想使用诸如自定义文本式文档页面等功能，就可能需要创建和修改它们。

rosdoc2.yaml
^^^^^^^^^^^^

这是 rosdoc2 的主要入口点。
它指定通用设置，可用于控制特定构建器（Doxygen 和 Sphinx）的执行，并决定运行哪些构建器。

``rosdoc2`` 提供了大量配置选项，可以在配置文件 ``rosdoc2.yaml`` 中进行调整。
要生成一个你可以进一步自定义的默认 ``rosdoc2.yaml``，请运行：

.. code-block:: console

   $ rosdoc2 default_config --package-path <package-path>

并将 ``<rosdoc2>rosdoc2.yaml</rosdoc2>`` 添加到 ``package.xml`` 的 export 部分：

.. code-block:: xml

    <package>
        <!-- [...] -->
        <export>
            <!-- [...] -->
            <rosdoc2>rosdoc2.yaml</rosdoc2>
        </export>
    </package>

但是，对于大多数包来说，``rosdoc2`` 中的默认设置就足够了，不需要自定义配置。
有关 ``rosdoc2.yaml`` 的更多信息，请参见 `rosdoc2 readme <https://github.com/ros-infrastructure/rosdoc2#using-a-rosdoc2yaml-file-to-control-how-your-package-is-documented>`__。

conf.py、rosdoc2_settings
^^^^^^^^^^^^^^^^^^^^^^^^^

包文档的最终输出（几乎）总是由 Sphinx 构建的。
每个 Sphinx 项目都由 ``doc`` 目录中的 ``conf.py`` 文件配置。
如果没有配置，则在构建文档时会创建并使用默认的 Sphinx 项目。
但是，如果在包的 ``doc`` 子目录中找到 ``conf.py`` Sphinx 配置，则会改用该配置。
如果你想包含一个独立的 reStructuredText 文档页面，则需要一个自定义的 Sphinx 项目。
独立文档页面可用于列出多个教程和指南；如果你希望为你的包实现这一点，就需要创建一个自定义的 Sphinx 项目。

``rosdoc2`` 会向 ``conf.py`` 提供额外的设置，并覆盖其中一些设置。
关于对 Sphinx 设置所做更改的信息会以 ``[rosdoc2]`` 前缀记录到控制台。

Doxyfile
^^^^^^^^

Doxygen 是一种根据代码注释自动生成 C++ API 文档的工具。
虽然 Doxygen 也可以直接生成 HTML 输出，但在 ROS 包的常规工作流程中，Doxygen 会生成 XML 格式的机器可读输出，然后由 Sphinx 消费并与其他文档集成。
通过只在 ``rosdoc2.yaml`` 中启用 Doxygen 构建器，可以只使用 Doxygen 生成文档，但这并不常见。

自定义 Sphinx 文档
------------------

创建 Sphinx 项目
^^^^^^^^^^^^^^^^

除了自动生成的 API 文档之外，要添加独立文档页面，需要一个自定义的 Sphinx 项目。
它应该创建在包目录中名为 ``doc`` 的子目录中。
可以通过在 ``doc`` 目录中运行 ``sphinx-quickstart`` 来创建新的 Sphinx 项目，对 "Separate source and build directories" 回答 ``no``。
该向导要求输入项目名称、作者和版本，但这些之后可以删除，并且将由 ``rosdoc2`` 从你的包的 ``package.xml`` 中提供给 Sphinx。
有关创建 Sphinx 项目的更多信息，请参见 `Sphinx quickstart 页面 <https://www.sphinx-doc.org/en/master/usage/quickstart.html>`__。

自定义 ``index.rst``
^^^^^^^^^^^^^^^^^^^^

``sphinx-quickstart`` 向导会创建一个 ``index.rst`` 文件，它是你的包的自定义落地页，类似于 GitHub 的 ``README`` 文件。

添加 Python API 文档
^^^^^^^^^^^^^^^^^^^^

默认情况下，``rosdoc2`` 使用 `sphinx-apidoc 工具 <https://www.sphinx-doc.org/en/master/man/sphinx-apidoc.html>`__ 和 `autodoc Sphinx 扩展 <https://www.sphinx-doc.org/en/master/usage/extensions/autodoc.html>`__ 自动为 Python 代码生成文档。
为了让 autodoc 找到你包中的 Python 模块，必须将其添加到 ``conf.py`` 中的 Python 搜索路径：

.. code-block:: python

    sys.path.insert(0, os.path.abspath('.'))

这是因为 ``rosdoc2`` 会用放置在包中的脚本提供的更多配置来包裹自定义的 ``conf.py``。
在这种情况下，由于 rosdoc2 与 ``conf.py`` 之间的交互，``os.path.abspath`` 中的 ``.`` 路径指的是包的目录根目录，而不是包的 ``doc`` 目录。

默认情况下，包的 API 文档已经可以通过落地页上的 "Module Index" 链接访问。
要让 API 文档也出现在目录中，只需向你的 ``index.rst`` 添加一个指向 ``modules`` 页面的链接：

.. code-block:: rst

    .. toctree::
       :maxdepth: 2
       :caption: Contents:

       Python Modules <modules>

添加 C++ API 文档
^^^^^^^^^^^^^^^^^

如果你希望将自动生成的 API 文档添加回你的自定义落地页，请将 ``generated/index`` 这一行添加到你的文档页面中你希望 API 文档出现的位置：

.. code-block:: rst

   .. toctree::
      :maxdepth: 2

      C++ API Docs <generated/index>

这会将 "Class Hierarchy"、"File Hierarchy" 和 "Reference" 元素添加到侧边栏的目录中。
要让这些元素出现在一个 "C++ API Docs" 标题下以使侧边栏不那么杂乱，可以添加一个单独的文件，例如 ``cpp_api_docs.rst``，它链接到生成的文档：

.. code-block:: rst
    :caption: cpp_api_docs.rst

    C++ API Docs
    ============

    These are the autogenerated docs for the internal implementation.

    .. toctree::
       :maxdepth: 3
       :caption: Contents:

       generated/index

然后还需要在 ``index.rst`` 中添加它，才能出现在侧边栏中：

.. code-block:: rst
    :caption: index.rst

    .. toctree::
       :maxdepth: 2
       :caption: Contents:

       cpp_api_docs


包含现有的 README.md
--------------------

如果你的 git 仓库已经有一个现有的 ``README.md``，可以将其复用为文档的落地页，而无需重复内容。
要在 Sphinx 中正确包含 Markdown 文件，同时保留相对链接和图片，需要做一些额外的工作。

首先，在 ``index.rst`` 旁边创建一个代理文件 ``readme_include.md``。
这是一个仅包含原始 README.md 的 Markdown 文件，但它保留了相对图片路径，否则这些路径会在下一步中被破坏：

.. code-block:: markdown
    :caption: readme_include.md

    ```{include} ../README.md
    :relative-images:
    ```


然后，使用 ``myst`` 从 ``index.rst`` 中包含此文件的内容，以从 rst 中包含 markdown：

.. code-block:: rst
    :caption: index.rst

    .. include:: readme_include.md
       :parser: myst_parser.sphinx_


这还需要将 ``myst_parser`` 添加到 ``conf.py`` 的扩展中：

.. code-block:: python
    :caption: conf.py

    extensions = ["myst_parser"]


CI、docs.ros.org
----------------

ROS 构建农场使用 ``rosdoc2`` 构建托管在 ``docs.ros.org/en/<distro>/p/<package>/`` 的包文档。
要启用此功能，包含文档的仓库必须在 `rosdistro/{DISTRO}/distribution.yaml <https://github.com/ros/rosdistro/blob/master/{DISTRO}/distribution.yaml>`__ 中配置。
这通常是包的源代码仓库：

.. code-block:: yaml

      <package_name>:
        doc:
          type: git
          url: https://github.com/<github_username>/<package_name>.git
          version: main
        release:
        [...]

构建农场会为每个发行版分别托管文档，并根据指定分支上的最新提交定期重建。
更新托管的文档不需要打新的发布标签。
要查看你的包文档构建的状态，请在 `<https://build.ros2.org>`__ 上搜索 ``doc__<package_name>``。
为包发布的每个发行版都会创建一个作业。
在每个作业页面上，你可以看到构建上次触发的时间，以及每次构建的状态和日志。
