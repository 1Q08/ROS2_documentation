编写 ROS 2 软件包文档
#####################

.. contents:: 目录
   :depth: 2
   :local:


本指南介绍为 ROS 2 软件包创建文档的标准方式。
对于有二进制发布的软件包，这还会使文档托管在 ``docs.ros.org/en/<distro>/p/<package>/``。
关于如何为 docs.ros.org 上的这份文档做贡献，请参阅 :doc:`为 ROS 2 文档做贡献 <../The-ROS2-Project/Contributing/Contributing-To-ROS-2-Documentation>`。

前提条件
--------

- :doc:`安装 ROS <../../Installation>`

- `安装 rosdoc2 <https://github.com/ros-infrastructure/rosdoc2#installation>`__

软件包文档概述
--------------

本指南讨论的文档类型被称为“软件包文档”或“API 文档”。
对于已在 ROS Index 上发布的 ROS 软件包，其文档会在 ROS 构建农场上构建，收录到 docs.ros.org，并可以通过 index.ros.org 上的 ``API Docs`` 按钮查看。

负责生成 ROS 2 软件包文档的工具是 `rosdoc2 <https://github.com/ros-infrastructure/rosdoc2>`__。

``rosdoc2`` 是对常用文档框架 `Sphinx <https://www.sphinx-doc.org/>`__ 的便捷封装。
Sphinx 既支持自由撰写形式的文档，也支持根据代码中的注释为 python 代码生成 API 文档。
`breathe <https://breathe.readthedocs.io/en/latest/>`__ + `exhale <https://exhale.readthedocs.io/en/latest/>`__ 软件包允许与 Doxygen 集成，从而也包含自动生成的 C++ API 文档。

``rosdoc2`` 会为完全没有文档或配置的软件包创建默认配置，并应用统一的主题以及与其他软件包集成的选项。

构建软件包文档
--------------

要用 ``rosdoc2`` 以 HTML 格式生成软件包的文档，请运行：

.. code-block:: console

   $ rosdoc2 build --package-path <package-path>

文档会写入 ``docs_output/<package-name>/index.html``，可以在浏览器中查看。

配置
----

ROS 软件包文档有三个配置位置：用于通用设置的 ``rosdoc2.yaml``、
用于 sphinx 设置的 ``conf.py``，以及用于 doxygen 设置的 ``Doxyfile``。
对于所有这些文件，如果不存在都会假定或生成默认值，因此它们都不是严格必需的。
不过，当你想要使用诸如自定义文本式文档页面这类功能时，可能就需要创建并修改它们。

rosdoc2.yaml
^^^^^^^^^^^^

这是 rosdoc2 的主入口点。
它指定通用设置，可用于控制特定构建器（Doxygen 和 Sphinx）的执行，并决定要运行哪些构建器。

``rosdoc2`` 提供了大量配置选项，可以在配置文件 ``rosdoc2.yaml`` 中进行调整。
要生成一份之后可以进一步自定义的默认 ``rosdoc2.yaml``，请运行：

.. code-block:: console

   $ rosdoc2 default_config --package-path <package-path>

并向 ``package.xml`` 中的 export 部分添加 ``<rosdoc2>rosdoc2.yaml</rosdoc2>``：

.. code-block:: xml

    <package>
        <!-- [...] -->
        <export>
            <!-- [...] -->
            <rosdoc2>rosdoc2.yaml</rosdoc2>
        </export>
    </package>

不过，对大多数软件包来说，``rosdoc2`` 中的默认设置就足够，无需自定义配置。
关于 ``rosdoc2.yaml`` 的更多信息可以在 `rosdoc2 readme <https://github.com/ros-infrastructure/rosdoc2#using-a-rosdoc2yaml-file-to-control-how-your-package-is-documented>`__ 中找到。

conf.py、rosdoc2_settings
^^^^^^^^^^^^^^^^^^^^^^^^^

软件包文档的最终输出（几乎）总是由 Sphinx 构建。
每个 Sphinx 项目由 ``doc`` 目录中的 ``conf.py`` 文件进行配置。
如果没有配置，则会创建一个默认的 Sphinx 项目并在构建文档时使用。
但如果在该软件包的 ``doc`` 子目录中找到 ``conf.py`` Sphinx 配置，则会改用该配置。
如果你想要包含独立的 reStructuredText 文档页面，就需要自定义的 Sphinx 项目。
独立文档页面可用于列出多个教程和指南；如果你的软件包需要这样做，就得创建一个自定义的 Sphinx 项目。

``rosdoc2`` 为 ``conf.py`` 提供了额外设置，并覆盖了其中一些设置。
关于对 Sphinx 设置所做更改的信息会以 ``[rosdoc2]`` 前缀记录到控制台。

Doxyfile
^^^^^^^^

Doxygen 是一个根据代码注释自动生成 C++ API 文档的工具。
虽然 Doxygen 也可以直接生成 HTML 输出，但在 ROS 软件包的常见工作流程中，Doxygen 会生成 XML 格式的机器可读输出，然后由 Sphinx 消费并与文档的其余部分集成。
只启用 ``rosdoc2.yaml`` 中的 Doxygen 构建器就可以只生成 Doxygen 文档，但这种情况并不常见。

自定义 Sphinx 文档
------------------

创建 Sphinx 项目
^^^^^^^^^^^^^^^^

为了在自动生成的 API 文档之外添加独立文档页面，需要自定义的 Sphinx 项目。
它应创建在该软件包目录下名为 ``doc`` 的子目录中。
可以在 ``doc`` 目录中运行 ``sphinx-quickstart`` 来创建新的 Sphinx 项目，对“Separate source and build directories”回答 ``no``。
该向导需要输入项目名称、作者和版本，但之后可以删除，``rosdoc2`` 会从你软件包的 ``package.xml`` 中提供给 Sphinx。
关于创建 sphinx 项目的更多信息可以在 `Sphinx quickstart page <https://www.sphinx-doc.org/en/master/usage/quickstart.html>`__ 上找到，

自定义 ``index.rst``
^^^^^^^^^^^^^^^^^^^^

``sphinx-quickstart`` 向导会创建一个 ``index.rst`` 文件，它是你软件包的自定义落地页，类似于 Github 的 ``README`` 文件。

添加 Python API 文档
^^^^^^^^^^^^^^^^^^^^

默认情况下，``rosdoc2`` 使用 `sphinx-apidoc 工具 <https://www.sphinx-doc.org/en/master/man/sphinx-apidoc.html>`__ 和 `autodoc Sphinx 扩展 <https://www.sphinx-doc.org/en/master/usage/extensions/autodoc.html>`__ 来自动为 python 代码生成文档。
为了让 autodoc 找到你软件包中的 Python 模块，必须把它添加到 ``conf.py`` 中的 python 搜索路径：

.. code-block:: python

    sys.path.insert(0, os.path.abspath('.'))

这是因为 ``rosdoc2`` 会用放置在该软件包中的脚本所提供的更多配置来包装自定义的 ``conf.py``。
在这种情况下，由于 rosdoc2 与 ``conf.py`` 的交互方式，``os.path.abspath`` 中的 ``.`` 路径指的是该软件包的目录根，而不是该软件包的 ``doc`` 目录。

默认情况下，通过落地页上的“Module Index”链接就已经可以访问软件包的 API 文档。
要让 API 文档也出现在目录中，只需向 ``index.rst`` 添加指向 ``modules`` 页面的链接：

.. code-block:: rst

    .. toctree::
       :maxdepth: 2
       :caption: Contents:

       Python Modules <modules>

添加 C++ API 文档
^^^^^^^^^^^^^^^^^

如果你想把自动生成的 API 文档添加回你的自定义落地页，请在你的文档页面中希望 API 文档出现的位置添加 ``generated/index`` 这一行：

.. code-block:: rst

   .. toctree::
      :maxdepth: 2

      C++ API Docs <generated/index>

这会把“Class Hierarchy”、“File Hierarchy”和“Reference”这些条目添加到侧边栏的目录中。
为了让它们出现在一个“C++ API Docs”标题之下，从而让侧边栏不那么杂乱，可以添加一个单独的文件（例如 ``cpp_api_docs.rst``）来链接到生成的文档：

.. code-block:: rst
    :caption: cpp_api_docs.rst

    C++ API Docs
    ============

    These are the autogenerated docs for the internal implementation.

    .. toctree::
       :maxdepth: 3
       :caption: Contents:

       generated/index

然后还需要在 ``index.rst`` 中添加它，才能在侧边栏中显示：

.. code-block:: rst
    :caption: index.rst

    .. toctree::
       :maxdepth: 2
       :caption: Contents:

       cpp_api_docs


包含已有的 README.md
--------------------

如果你的 git 仓库中已经有了 ``README.md``，可以把它复用为文档的落地页，而不必重复其内容。
要在 Sphinx 中正确包含 Markdown 文件并保留相对链接和图片，还需要做一些额外的工作。

首先，在 ``index.rst`` 旁边创建一个代理文件 ``readme_include.md``。
这是一个仅包含原始 README.md 的 markdown 文件，但它保留了相对图片路径，否则这些路径会在下一步中失效：

.. code-block:: markdown
    :caption: readme_include.md

    ```{include} ../README.md
    :relative-images:
    ```


然后，从 ``index.rst`` 中使用 ``myst`` 包含该文件的内容，从而在 rst 中包含 markdown：

.. code-block:: rst
    :caption: index.rst

    .. include:: readme_include.md
       :parser: myst_parser.sphinx_


这还需要把 ``myst_parser`` 添加到 ``conf.py`` 中的 extensions：

.. code-block:: python
    :caption: conf.py

    extensions = ["myst_parser"]


CI、docs.ros.org
----------------

ROS 构建农场使用 ``rosdoc2`` 来构建托管在 ``docs.ros.org/en/<distro>/p/<package>/`` 的软件包文档。
要启用这一点，必须在 `rosdistro/{DISTRO}/distribution.yaml <https://github.com/ros/rosdistro/blob/master/{DISTRO}/distribution.yaml>`__ 中配置包含该文档的仓库。
这通常是该软件包的源码仓库：

.. code-block:: yaml

      <package_name>:
        doc:
          type: git
          url: https://github.com/<github_username>/<package_name>.git
          version: main
        release:
        [...]

构建农场为每个发行版分别托管文档，并定期根据指定分支上的最新提交重新构建。
更新托管的文档不需要打新的发布标签。
要查看你软件包文档构建的状态，请在 `<https://build.ros2.org>`__ 上搜索 ``doc__<package_name>``。
软件包每发布一个发行版就会创建一个作业。
在每个作业页面上，你可以看到上次触发构建的时间，以及每次构建的状态和日志。
