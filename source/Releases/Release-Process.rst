发行版的开发流程
================

.. contents:: 目录
   :depth: 2
   :local:

每个 ROS 2 发行版都要经历一个长达一年多的开发流程，该流程在前一个发行版发布之前就已经开始。
以下是该开发流程的概要视图。
该流程中的各项没有具体的截止日期，但一般来说，前项应在后项可以完成之前完成。

有关某个具体发行版在此流程中的进度，请参见该发行版的文档页面。

.. list-table::
   :class: release-process
   :header-rows: 1
   :widths: 30 70

   * - 事项
     - 说明
   * - 选定 ROS Boss
     - "ROS Boss" 是负责引导发行版走过其生命周期的开发、发布、更新和停止维护（EOL）各阶段的人。他们从 Open Robotics 内部的 ROS 2 团队中选出。
   * - 运行选择发行版名称的流程
     - ROS Boss 负责主持选择发行版名称的流程，参考社区等来源的意见以及潜在命名冲突。
   * - 创建发行版的文档页面
     - 每个发行版都有一个文档页面，列出其关键信息，如计划发布日期、停止维护日期以及自上一个版本以来的重要变更。
   * - 设定发布时间线
     - 发布日（通常是世界海龟日）前的最后几周非常忙碌，充满了各种截止日期，例如何时冻结默认 RMW 实现。这些截止日期必须提前做好规划。
   * - 制定路线图
     - 虽然 ROS 的每位贡献者对每个发行版都有自己的计划功能，但我们会尽力维护一份整体路线图，列出我们期望在该发行版中看到的新功能和重要变更。ROS Boss 和 Open Robotics 的 ROS 2 开发团队负责人与 ROS 2 TSC 及其他相关方合作，制定一份在可用时间内可实现且满足 ROS 社区需求的路线图。
   * - 公布路线图
     - 计划功能和重要变更的列表通过一个 GitHub issue 公之于众，该 issue 将跟踪路线图中每一项的开发进度。当然，这并不意味着路线图在此时就固定不变，因为开发计划可能会改变，而且即使不在计划路线图内，我们也始终（并且经常）欢迎新的贡献。
   * - 设定目标平台和主要依赖
     - 目标平台（就操作系统、发行版和版本而言）必须提前足够久设定好，以便基础设施（如构建农场中的支持）的开发工作得以推进。同样，每个主要依赖的版本（使用哪个 Python 版本、哪个编译器、哪个版本的 Eigen 等）也必须确定下来。这通过更新 `REP-2000 <https://reps.openrobotics.org/rep-2000/>`__ 来完成。
   * - 向构建农场添加平台支持
     - 构建农场是支撑 ROS 2 发行版的基础设施的关键部分。它提供持续集成设施，帮助我们保持质量，并构建社区所依赖的二进制软件包，从而避免从源代码构建 ROS 2 和软件包。如果目标平台与前一个 ROS 2 发行版不同，则必须向构建农场添加必要的支持。
   * - 委托设计徽标和相关美术作品
     - 每个 ROS 2 发行版（以及 ROS 发行版！）中深受喜爱的一部分就是徽标。徽标根据选定的发行版名称委托专业艺术家设计。在徽标的基础上，还会制作其他美术作品，如 turtlesim 图标。
   * - 为发行版创建邮件列表
     - 邮件列表对于发布重要公告至关重要，必须建立邮件列表来联系那些希望了解发行版相关信息的人，例如他们的软件包在构建农场上构建二进制失败的情况。
   * - 创建测试用例
     - 随着开发流程进入最后几个月，测试工作开始全面展开。必须编写开发最后阶段将使用的集成测试用例，并提供给负责执行它们的发布团队。
   * - 宣布即将到来的 RMW 冻结
     - RMW 冻结是新发行版的默认 RMW 实现功能冻结的时间点。这为开发者提供了一个稳定的测试目标，对客户端库开发者尤为重要，因为他们需要知道 RMW 层的哪些功能可供客户端库使用。
   * - 升级依赖软件包
     - ROS 所依赖但并非 ROS 软件、且平台软件包管理器（如 Ubuntu 的 aptitude）中不可用的软件包，即所谓的"供应商软件包"，必须更新到 REP-2000 中指定的版本（对于未在 REP-2000 中列出的，则使用适当的版本）。这在 Windows 上尤为重要。
   * - 制定详细的发布计划
     - 对开发流程的最后两个月进行规划。这将产出一份详细的测试计划、某些软件包必须在何时就绪的时间线等。它能够发现发布流程中各步骤之间的依赖关系，并找到执行每个步骤的人选。
   * - 冻结 RMW
     - RMW 实现现已功能冻结。理论上，现在可以对它进行详尽的测试，以确保在发布日之前它能正常工作。
   * - 宣布即将到来的整体冻结
     - 冻结 RMW 实现之后的下一个冻结是整个发行版的冻结。此时核心 ROS 软件包功能冻结，为非核心软件包的开发者提供稳定的测试目标，也为发行版测试人员提供了测试后不会立即变动的内容。
   * - 冻结发行版
     - 从此以后，任何核心 ROS 软件包都不能再添加新功能。只有在密集的集成测试阶段发现的（不可避免的）缺陷的修复才能合入代码库。这意味着 Rolling Ridley 实际上被临时冻结了。
   * - 宣布即将到来的分支
     - 新 ROS 2 发行版从 Rolling Ridley 分支出来是一个重要时刻，值得做好准备。
   * - 宣布即将到来的 beta
     - 当发行版进入 beta 阶段时，它就可以供 ROS 社区进行更广泛的测试。这个 beta 会在发行版从 Rolling Ridley 分支后不久到来。
   * - 从 Rolling Ridley 分支
     - 新 ROS 2 发行版通过从 Rolling Ridley 创建新分支来诞生。实际上，新发行版就在这个时间点诞生。与此同时，Rolling Ridley 摆脱了开发流程的束缚，可以继续滚动前进，再次接收新功能。
   * - 将发行版加入 CI
     - 持续集成系统经过更新，允许使用新发行版的分支和核心 ROS 软件包进行构建。这意味着软件包开发者可以针对新发行版（而不是 Rolling Ridley）为他们的软件包运行 CI。
   * - 开始构建临时测试压缩包
     - 即将对新发行版进行检验的精英测试团队需要一些东西来测试，而不必不断从源代码编译 ROS 2。构建农场用于生成一组包含某个时间点发行版状态的压缩包，供测试人员测试。
   * - 添加发行版文档
     - 有关发行版的详细文档（例如自上一个发行版以来的重要变更）被添加到 ROS 2 文档网站。
   * - 宣布 beta
     - 发行版的 beta 版本发布，并邀请整个 ROS 社区参与测试（面向那些尚未参与测试的人）。此时，测试人员越多越好，因为发行版需要尽可能广泛地经过各种场景的检验，以便在发布前发现缺陷。
   * - 最终的发布准备
     - 随着新发行版进入"绝对完全全面冻结"阶段，发布前的最终准备工作开始进行。其中包括使用构建农场生成二进制软件包，以便有东西可以发布。
   * - 发布
     - 这是大日子，如果一切按计划进行，正好赶上 5 月 23 日的世界海龟日。发行版的二进制软件包在发布仓库中提供，并发布公告。举行庆祝活动，ROS 2 开发团队享受应得的休息。
